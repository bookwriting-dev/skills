## Books and shared canon

This repo holds a series, so everything is either **shared series canon** or **per-book**. Shared canon never moves into a book folder; per-book work never sits loose at a root.

- **Shared (Wiki root):** `Wiki/Characters/`, `Wiki/World/` (including `Wiki/World/Systems/` for LitRPG mechanics and `ledger.yaml`), `Wiki/Style/`, `Wiki/Story/theme.md`, `Wiki/Story/synopsis.md` (the series synopsis), `Wiki/Story/series-arc.md` (the series-level plan maintained by `fiction-series-outline`), `Wiki/Story/active-context.md` (the working log for the whole series), and `Wiki/Review/` (the series review panel — build it when Book 1 reaches review).
- **Per-book (`Book-N/` subfolders):** every book gets the same five slots, whether or not they are filled yet — `Wiki/Story/Book-N/` (book synopsis, revision plans, `promises.yaml` — the Chekhov ledger, and `kanban.md` — the production board regenerated by `kanban-board`), `Wiki/Outline/Book-N/` (outline + `Chapter_NN_Scene.md` beats + `surprise-ledger.md`), `Wiki/Psych/Book-N/`, `Chapters/Book-N/`, `_Edits/Book-N/`.
- Older entries in `active-context.md` may cite pre-reorg root paths (e.g. `Chapters/Chapter-035.md`); the moved location is under `Book-N/`.

## Authority

1. The user's current instructions.
2. This file (`AGENTS.md`).
3. Established Wiki files for this book.
4. The invoked skill's instructions.
5. Generic defaults in a skill.

If Wiki and a draft disagree, Wiki wins until the user explicitly changes canon. If a skill would create a proper noun that is not in Wiki, stop and say so rather than inventing it.

`_Intake/` holds authorial raw material, brainstorming, voice dictations, and external manuscripts staged for reverse-engineering. It is **inspirational and advisory**: skills read it to avoid interrogating you from scratch, but it does not override established `Wiki/` canon once formalized.

## How to start a book (FICTION)

There are two doors into a book project:

### Path A: Greenfield (Starting from a new idea or brief)

1. Review or fill `_Intake/series-brief.md` (and `_Intake/Book-1/premise.md`). Drop stray brainstorms or voice dictations into `_Intake/Book-1/raw-notes/`.
2. Run the planning skills in order. They check `_Intake/` first and pre-populate context rather than interrogating you in a vacuum:
   1. `fiction-genre` → `Wiki/Style/genre.md`
   2. `fiction-audience` → `Wiki/Style/audience.md`
   3. `fiction-theme` → `Wiki/Story/theme.md`
   4. `fiction-synopsis` → `Wiki/Story/synopsis.md`
   5. `fiction-series-outline` → `Wiki/Story/series-arc.md` (at series inception; refresh before planning each later book)
   6. `fiction-characters` → `Wiki/Characters/`
   7. `fiction-world` (and `fiction-places` / `fiction-factions` / `fiction-polities` / `fiction-religions` as needed)
   8. `litrpg-system` → `Wiki/World/Systems/` + character sheets + `ledger.yaml` (if writing LitRPG or Progression Fantasy)
   9. `fiction-outline` → `Wiki/Outline/Book-N/outline.md`
   10. `fiction-divergence` → beat-the-defaults pass over the outline, plus the per-act surprise ledger
   11. `fiction-psych` → `Wiki/Psych/Book-N/`
   12. `fiction-scenes` → chapter beat plans (slicing active `relationship_checkpoints` and enforcing micro-friction per scene)
   13. `fiction-style` + `fiction-voiceprompt` (writes `voice_prompt.md` and per-POV `voice_prompt_<Name>.md` files for dual/multi-POV books)
   14. `fiction-writechapter` → compiles `_Edits/Book-N/packets/Chapter-NNN_DraftPacket.json` (continuity tail, active relationship checkpoints, psych `what_they_wont_say`, knowledge as-of, and trailing 3-chapter cooling list) and drafts `Chapters/Book-N/Chapter-NNN.md` scene by scene
   15. `fiction-reviewchapter` / `gate-check` (runs canon, relationship checkpoint, subtext/dialogue architecture, cooling list, Chekhov ledger, knowledge, and `litrpg-audit` checks)
   16. `review-panel` per act and before calling the book done; `drift-check` at part boundaries

### Path B: Brownfield (Reverse-engineering an existing or unguided draft)

If you already have a drafted or finished manuscript that was written without Storycraft discipline:

1. **Stage the manuscript:** Place it in `_Intake/Book-N/raw-manuscript/` (or scaffold with `./new-book.sh my-book "My Book" --import /path/to/manuscript`).
2. **Analyze (`book-reverse-engineer`):** Reads the chapters, normalizes units to `Chapters/Book-N/Chapter-NNN.md`, and produces `_Edits/Book-N/reverse-analysis.md` extracting characters, world rules, timeline, Chekhov promises, and voice DNA. Flags all `CANON CONFLICT` and `DROPPED THREAD` discrepancies.
3. **Review & Canon Lock:** Review the analysis report's discrepancy punch list. Make the binding canon decisions where the text contradicted itself.
4. **Import:** The skill writes the authoritative `Wiki/` canon, `Wiki/Story/Book-N/promises.yaml`, retrofitted beats in `Wiki/Outline/Book-N/`, and seeds `_Edits/Book-N/findings.yaml`.
5. **Rebuild & Repair Loop:**
   - Structural / developmental fixes: `fiction-dev-editor`
   - Targeted scene & chapter fixes: `fiction-revise` against the locked `Wiki/`
   - Validation & gating: `fiction-reviewchapter` / `gate-check`

`fiction-story-sparks` is only for an explicit prompt, card-style idea, or writing exercise. Do not use it to start or rewrite this book unless asked. For a second book, run `fiction-series-outline` first to refresh `Wiki/Story/series-arc.md` and honor the handoff inventory and inter-book promise map; the already-canonical series-level steps (genre, audience, theme, series synopsis, characters, world, style) are skipped unless the book needs new entries, and the book starts at its own synopsis in `Wiki/Story/Book-N/`.

4. `nonfiction-chapter-plan` → `Wiki/Outline/Book-N/plan.md`
5. `nonfiction-writechapter` → `Chapters/Book-N/Chapter-NNN.md`
6. `nonfiction-factcheck` → `_Edits/Book-N/Chapter-NNN_FactCheck.md`
7. `nonfiction-clarity-edit` → `_Edits/Book-N/Chapter-NNN_ClarityEdit.md`

## Chapter files

Default path: `Chapters/Book-N/Chapter-NNN.md` (three-digit). Put the chapter title inside the file, with the POV name(s) beneath the title. Review reports go to `_Edits/Book-N/Chapter-NNN_Review.md` (three-digit, matching the chapter).

## Naming and place generation

When inventing proper nouns or locations, route to the specific generator:
- **People / character names:** `name-generator`. Do not freehand names. Before a generated name enters canon, collision-check it against existing fiction, games, and brands; deliberately anonymous characters stay unnamed.
- **Town / settlement names:** `town-generator` (lexical naming only).
- **Full settlement profiles:** `fantasy-settlement` (complete dossier with population, economy, districts, security).
- **Scene-bearing sites / landmarks:** `fiction-places` (ruins, rooms, wilderness sites, tactical locations; not full towns).

**Non-fiction:** proper nouns are real — never run the generators. Names, places, and terms come from research with sources, and `nonfiction-factcheck` audits them.

## Editing

Do not run a kill pass or full edit unless the user asked for revision.

Structural review findings — required beats missing or misfired, wrong POV architecture, a canon breach baked through the chapter — are not editing jobs: fix the scene plan or brief and re-draft the chapter with `fiction-writechapter` (fiction) or `nonfiction-writechapter` (non-fiction). Editing passes are for localizable problems.

Route editing and review tasks using this decision tree:

**Fiction:**
- **Story structure / causality / "does this chapter move?":** `fiction-dev-editor`. Diagnose scene beats, pacing, and causality before touching lines.
- **Chapter gate (default review):** `fiction-reviewchapter` for a full review of a finished draft; `gate-check` for the lighter checklist gate over the same pillars — and it is the one `chapter-pipeline` runs. Both cover canon assertions, Chekhov setups, character consistency, prose rules, and (for LitRPG) progression continuity.
- **LitRPG progression / stat continuity:** `litrpg-audit`. Deterministic mechanical check of stat point math, level curves, and skill unlocks against `ledger.yaml`. Also runs inside `gate-check`.
- **Dialogue-only failure (samey, interview-like, expository):** `fiction-dialogue`. Diagnose conversation architecture and speaker stakes before diction.
- **Blind POV / voice test:** `coldread`. Read-only, run in isolation before rule-loaded review so house rules do not prime the reader.
- **Loose ends and unpaid setups:** `fiction-promises`. Audits the per-book Chekhov ledger (`promises.yaml`).
- **Sentence-level revision (default):** `fiction-full-editor`. Scans micro-level craft, AI-isms, and line edits in one pass. Use layer-specific scanners (`fiction-line-editor`, `fiction-prose-editor`, `fiction-aiism-editor`) only when specifically targeting that single layer.
- **Applying approved review/edit fixes:** `fiction-revise`. Applies user-approved items from `_Edits/` reports in place with strict quote verification, minimal perturbation, and a change ledger.
- **Recurring model crutches (default):** `kill-chapter`. Runs all seven kill passes consecutively in place (similes, person-who, opinion-personification, the-whole, crutch, soft, flat). Use single-kill passes (`kill-crutch WORD`, `kill-simile`, `kill-the-whole`, `kill-person-who`, `kill-opinion-personification`) only when targeting a specific token.
- **Book-level drift / back-half flatness / formula openers:** `drift-check` across part boundaries and chapters.
- **Reader reaction / persona reads:** `review-panel` for act- and book-level QA; `reader-persona-review` for a quick scored archetype pulse on a single chapter. Both grep-verify quoted lines.

**Non-Fiction:**
- **Structural / argument flow / "does this chapter prove?":** `nonfiction-dev-editor`. Diagnose argument architecture, claim scaffolding, and cognitive load before sentence edits.
- **Chapter gate (default review):** `nonfiction-factcheck` + `nonfiction-clarity-edit`. Fact/evidence verification first, then the clarity pass (jargon density, abstraction ladder, cognitive load, signposting).
- **Fact / evidence failure:** `nonfiction-factcheck`. Verifies every claim against the book's research corpus and cited sources.
- **Blind clarity / voice test:** `coldread`. Read-only, run in isolation before rule-loaded review so house rules do not prime the reader.
- **Unsupported claims / missing evidence:** `promise-tracker`. Audits the per-book promise/claim ledger (`promises.yaml`).
- **Sentence-level revision (default):** `nonfiction-clarity-edit`. Scans micro-level clarity, jargon, passive voice, and line edits in one pass.
- **Applying approved review/edit fixes:** `fiction-revise`. Report-driven and book-agnostic — it applies user-approved items from any `_Edits/Chapter-NNN_*.md` report with strict quote verification and a change ledger.
- **Recurring clarity crutches:** run the targeted passes — `nominalization-hunt`, `kill-passive`, `kill-hedge`, `kill-acronym`. Use a single pass when targeting one pattern.
- **Book-level drift / argument coherence / thesis alignment:** `drift-check` across part boundaries and chapters.
- **Reader reaction / persona reads:** `review-panel` for act- and book-level QA (it ships non-fiction seats); `reader-persona-review` for a quick scored archetype pulse on a single chapter.

## Evidence, editorial memory, and book-wide revision

| Skill | Role |
|---|---|
| `editorial-memory` 1.0.0 | Explicit scoped author decisions; keep/reject history and reusable preferences. |
| `fiction-knowledge` 1.0.0 | Sourced character beliefs, secret acquisition, and reader exposure in story/reading order. |
| `sequential-read` 1.0.0 | Ordered simulated reader run with fresh isolated contexts and sealed predictions. |
| `revision-campaign` 1.0.0 | Dependent book/series revision tasks, snapshots, safe resume, and current verification. |

Drafting and review load applicable editorial decisions and current knowledge evidence. After draft generation, reconcile promise and knowledge harvest before gating. All changed prose requires a fresh final gate after polish. Review reports capture input hashes before review and emit metadata only if those inputs still match afterward. Status and the board show CURRENT/STALE/UNKNOWN separately from PASS/WARN/FAIL. Legacy reports remain UNKNOWN until re-reviewed. Pending blocking findings or campaign work prevent Done.

For fiction chapter gates, validate heading and POV metadata and review the chapter for source-linked identifiers, object state changes, clock anchors, and scoped counts. Run book-wide continuity before submission or publication. Use the installed [book continuity review](.agents/skills/book-status/references/continuity-review.md) instructions.

For a reading-experience test, use sequential-read; private canon and future text never enter reader packets. Prepare packets and report pending execution when isolated contexts are unavailable. For a coordinated change across chapters, use revision-campaign; inspect interrupted work before reuse. Compile a beta/submission/publication package with compile-manuscript after current checks. Required checks for non-fiction/hybrid projects are configured explicitly (FactCheck and ClarityEdit for the non-fiction workflow); a clarity report's existence alone cannot mark Done. Existing project conventions and current user instructions retain authority.
