# Updating existing book projects

Run `tools/update-project.sh PROJECT --migration` for a read-only report of updates, conflicts, and legacy reports without current metadata. Run with --apply to install safe new/changed library files; --prune removes only project-only files whose hashes still match the recorded installed base. Book manuscripts, Wiki content, instructions, editorial decisions, and review records are never copied over by this updater.

New scaffolds record .agents/skills/.storycraft-base.json. On update, files changed locally since that base are retained and reported. For older pins without base hashes, differing existing files have unknown ancestry and are retained as conflicts; identical incoming files establish a safe base. Resolve conflicts deliberately, rerun the updater, then review and commit locally when requested. An unresolved conflict retains the old source pin. Updating dependencies piecemeal can leave incomplete installations; use the full library and inspect dependency warnings.

Instruction templates are not overwritten. Reconcile their new evidence, knowledge, sequential-read, and revision workflow sections manually. Tracking files initialize lazily. No renumbering or complete Wiki reconstruction is necessary. Existing reports remain readable but UNKNOWN until reviewed again against captured source evidence. Never stamp a historical report as current merely because its prose still exists.

Version 1 project manifests remain readable. Explicit chapter registration writes version 2, which can hold planned chapters before their files exist. Update the pinned library when sharing a v2 project with another writer. Legacy numbered layouts continue to resolve from disk and their outline. Register a custom chapter or interlude with its stable ID, reading order, and destination. Future schema versions fail without rewriting; there is no speculative conversion or destructive automatic migration. Before any future migration, back up records and test repeated execution on a disposable copy. Initialization must adopt existing data rather than reseeding it. Proposed knowledge imported from earlier prose should remain unconfirmed until exact source evidence is checked.

Literary preferences require explicit scope and author intent; existing rejections can be imported as local dispositions without inventing broad rules. Missing knowledge coverage must remain visible. Project type comes from the existing declaration in AGENTS.md. The fiction default applies to untyped legacy projects. The book manifest can override required_checks for the workflow. An explicit export configuration still governs that export.

The manuscript importer uses a receipt to match prior imported files. On first use in an older book, preview and review any differing existing chapters. A prior beta edition needs a new export to get Word anchors and a passage map.
