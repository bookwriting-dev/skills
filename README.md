# storycraft-skills

Our fiction skill library — forked from [Open Storycraft](https://storycraft.lanternkey.fyi/) and independently developed. At the fork point it was the upstream's 42 skills; everything since is ours. See [CHANGELOG.md](CHANGELOG.md) for what we've changed and added, and why.

Each fiction project gets a pinned copy of `skills/` at `.agents/skills/` when scaffolded — skills stay project-local so every repo keeps its own git history and can fork its library freely.

## Layout

```
storycraft-skills/
├── skills/            # the skill library (ours since the 2026-10-10 fork)
├── templates/         # AGENTS.md + CLAUDE.md skeletons (__SERIES_TITLE__ placeholder)
├── tools/             # lint-skills.py · gen-inventory.py · compile-check.py · eval-skills.sh (+ eval-fixtures/) · smoke-new-book.sh · update-project.sh · skill_lib.py
├── Makefile           # `make check` — the validation gate (lint + inventory + syntax + behavior eval + scaffold smoke test)
├── VERSION            # library revision, recorded into each project's pin
├── new-book.sh        # scaffold a new series project
├── sync-check.sh      # diff against upstream to catch drift worth pulling
└── docs/              # DEVELOPER.md (library internals) · USER.md (workflow + catalog) · SKILL-INVENTORY.md (generated)
```

## Documentation

- **[docs/USER.md](docs/USER.md)** — the writing workflow from the outside: project layout, the fiction and non-fiction pipelines, the editing decision tree, all 78 skills with what they do and what to say to trigger them.
- **[docs/SKILL-INVENTORY.md](docs/SKILL-INVENTORY.md)** — the generated, always-current inventory of every skill (name, version, category, summary). Regenerated by `make inventory`; `make check` fails if it drifts.
- **[docs/DEVELOPER.md](docs/DEVELOPER.md)** — the library from the inside: skill anatomy and frontmatter contract, worker/orchestrator conventions, the change loop (version bump → CHANGELOG → manifest → template wiring), sync-check policy, and known gaps.

## Usage

```bash
./new-book.sh my-series "My Series Title"              # → ~/Projects/Books/my-series
BOOKS_DIR=/some/where ./new-book.sh my-series          # → /some/where/my-series
./new-book.sh my-thesis "My Thesis" --type nonfiction  # or hybrid — adds Wiki/Concept + Wiki/Research
```

The script creates the shared Wiki slots (`Characters/`, `World/`, `Style/`, `Review/`, `Story/`), Book 1's five per-book slots (`Story/Book-1/`, `Outline/Book-1/`, `Psych/Book-1/`, `Chapters/Book-1/`, `_Edits/Book-1/`), copies the skill library in, renders the two instruction files, records the pinned library revision in `.agents/skills/.storycraft-source`, and makes the initial git commit. From there, start the book with the planning skills in AGENTS.md's order (`fiction-genre` first).

To pull a newer library into an existing project:

```bash
tools/update-project.sh ~/Projects/Books/my-series            # dry run: show what changed
tools/update-project.sh ~/Projects/Books/my-series --apply    # copy it in, rewrite the pin
```

### Dual Distribution: Native Plugin + Local MCP Server

Run the following command with `uv` installed to build the generic plugin. It includes the skills, rendered project rules, stdio MCP server, release version, PyYAML, and review skill digests. The installed bundle needs Python 3.10 or newer. Set `STORYCRAFT_PYTHON` to select an interpreter.

```bash
make plugin-dist   # builds dist/storycraft-skills/
```

The `storycraft-state` MCP server exposes its typed tools through `tools/list`. To preflight a PDF with `storycraft_compile`, pass `formats: ["pdf"]` and an installed Pandoc engine such as `pdf_engine: "typst"`. Pass `config` with a project-relative export JSON file to use its title, front and back matter, or `pdf_engine`. A tool argument overrides the configured engine. Set `check: false` to build the package.

### Personal ChatGPT Desktop plugin

Run `make install-plugin` with `uv` and the Codex CLI installed. It builds `~/Plugins/storycraft/`, adds Storycraft to the local marketplace in `~/Plugins`, and refreshes the desktop install. Use `DESKTOP_PLUGIN_DIR` to select a different marketplace directory. The build includes PyYAML for the promise parser and records the local Python interpreter. Open a fresh local ChatGPT Desktop conversation with a manuscript workspace, select **Storycraft**, and ask for book status. Run the same command after a library update. Restart the desktop app if an open session still uses the previous package.

The desktop plugin supplies the shared skills and scripts. Each manuscript workspace supplies its book files and rules. For a repo with a pinned library, first inspect its local changes with `tools/update-project.sh PROJECT --migration`. When switching that repo to Storycraft Desktop, preserve any custom guidance in the repo, update its instructions to use the shared plugin, and retire its old skill copy through Git. Repos using the desktop plugin can share updates without per-repo installs.

### Claude Code plugin

Run these commands from the library checkout to build and install the local marketplace. The build uses `uv`. Claude needs Python 3.10 or newer and uses the packaged copy of PyYAML. Set `STORYCRAFT_PYTHON` in Claude's environment to select a specific interpreter.

```bash
make claude-plugin
claude plugin marketplace add "$PWD/dist/claude-marketplace"
claude plugin install storycraft@storycraft-local
```

You can also install from inside Claude Code with `/plugin marketplace add /absolute/path/to/dist/claude-marketplace` followed by `/plugin install storycraft@storycraft-local`. Open a manuscript repository and run `/storycraft:book-status`. Check the `plugin:storycraft:storycraft-state` connection with `/mcp`. For a one-session preview, use `claude --plugin-dir /absolute/path/to/dist/claude-marketplace/plugins/storycraft`. Set `CLAUDE_MARKETPLACE_DIR` to build elsewhere.

Both host packages use the same review evidence. A completed review can be opened on either host, and a review prepared on one can be finalized on the other. A changed manuscript input, report, or relevant editorial rule still makes the saved evidence stale. Run `make check-claude-plugin` to exercise an isolated marketplace install and both directions of the handoff. Set `CLAUDE_BIN` to choose a specific Claude Code executable.

## Development

Run `make check` before committing. It uses `uv` with the same pinned PyYAML version as the plugin builds.

```bash
make check     # lint frontmatter/paths/doc-drift + verify inventory + syntax-check all scripts + behavior eval + scaffold smoke test
make inventory # regenerate docs/SKILL-INVENTORY.md from frontmatter
make eval      # run the scripts against fixture chapters/ledgers with known defects
make smoke     # scaffold a throwaway project and assert the tree it produces
```

`tools/lint-skills.py` enforces the invariants the manual audits used to check by hand — skill name == folder, quoted semver, valid category, resolvable `references/`/`assets/`/`scripts/` paths, catalog versions matching frontmatter, and the "N skills" count matching reality. `tools/compile-check.py` syntax-checks every Python file in memory, runs `bash -n` over every shell script, and asserts the two ledger parsers agree; `tools/eval-skills.sh` runs the diagnostics and ledger scripts against fixtures with known defects (a chapter carrying callouts/fences with sentinel tokens, a deliberately monotone chapter, a mixed-format promise ledger) so behavior — not just shape — is gated; and `tools/smoke-new-book.sh` runs the scaffolder end-to-end against a scratch directory. See [docs/DEVELOPER.md](docs/DEVELOPER.md) for the full change loop.


## Lineage

- Fork origin: vendored from the mermaid project's `.agents/skills/` at its commit dc010ca (2026-09-11, project start) — at that point a verbatim copy of Open Storycraft.
- Verified against the upstream ZIP (`open-storycraft-structured.zip`, downloaded 2026-10-10): the only differences from upstream were our own pre-fork passes recorded in the CHANGELOG. Nothing upstream was dropped.
- Upstream has no public repo or changelog — the ZIP is its only distribution channel. Run `./sync-check.sh` to re-check for upstream drift; any differing file not accounted for in the CHANGELOG is upstream movement to review, not an obligation to take.
- This repo is the source of truth for our library. Changes are ordinary development: add a CHANGELOG entry, bump the skill's version in its frontmatter, and go. There is no re-apply-the-deltas ritual anymore.
