# storycraft-skills

Our fiction skill library — forked from [Open Storycraft](https://storycraft.lanternkey.fyi/) and independently developed. At the fork point it was the upstream's 42 skills; everything since is ours. See [CHANGELOG.md](CHANGELOG.md) for what we've changed and added, and why.

Each fiction project gets a pinned copy of `skills/` at `.agents/skills/` when scaffolded — skills stay project-local so every repo keeps its own git history and can fork its library freely.

## Layout

```
storycraft-skills/
├── skills/            # the skill library (ours since the 2026-10-10 fork)
├── templates/         # AGENTS.md + CLAUDE.md skeletons (__SERIES_TITLE__ placeholder)
├── tools/             # lint-skills.py · gen-inventory.py · compile-check.py · update-project.sh · skill_lib.py
├── Makefile           # `make check` — the CI gate (lint + inventory + syntax)
├── VERSION            # library revision, recorded into each project's pin
├── .github/           # CI: the same gate on push/PR (.github/workflows/ci.yml)
├── new-book.sh        # scaffold a new series project
├── sync-check.sh      # diff against upstream to catch drift worth pulling
└── docs/              # DEVELOPER.md (library internals) · USER.md (workflow + catalog) · SKILL-INVENTORY.md (generated)
```

## Documentation

- **[docs/USER.md](docs/USER.md)** — the writing workflow from the outside: project layout, the fiction and non-fiction pipelines, the editing decision tree, all 73 skills with what they do and what to say to trigger them.
- **[docs/SKILL-INVENTORY.md](docs/SKILL-INVENTORY.md)** — the generated, always-current inventory of every skill (name, version, category, summary). Regenerated by `make inventory`; `make check` fails if it drifts.
- **[docs/DEVELOPER.md](docs/DEVELOPER.md)** — the library from the inside: skill anatomy and frontmatter contract, worker/orchestrator conventions, the change loop (version bump → CHANGELOG → manifest → template wiring), sync-check policy, and known gaps.

## Usage

```bash
./new-book.sh my-series "My Series Title"              # → ~/Projects/Books/my-series
BOOKS_DIR=/some/where ./new-book.sh my-series          # → /some/where/my-series
./new-book.sh my-thesis "My Thesis" --type nonfiction  # or hybrid — adds Wiki/Concept + Wiki/Research
```

The script creates the shared Wiki slots (`Characters/`, `World/`, `Style/`, `Review/`, `Story/`), Book 1's five per-book slots (`Story/Book-1/`, `Outline/Book-1/`, `Psych/Book-1/`, `Chapters/Book-1/`, `_Edits/Book-1/`), copies the skill library in, renders the two instruction files, records the pinned library revision in `.agents/skills/.storycraft-source`, and makes the initial git commit. From there, start the book with the planning skills in AGENTS.md's order (`fiction-genre` first).

To pull a newer library into an existing project:

```bash
tools/update-project.sh ~/Projects/Books/my-series            # dry run: show what changed
tools/update-project.sh ~/Projects/Books/my-series --apply    # copy it in, rewrite the pin
```

## Development

The library has its own gate. Run it before committing:

```bash
make check     # lint frontmatter/paths/doc-drift + verify inventory + syntax-check all scripts
make inventory # regenerate docs/SKILL-INVENTORY.md from frontmatter
```

`tools/lint-skills.py` enforces the invariants the manual audits used to check by hand — skill name == folder, quoted semver, valid category, resolvable `references/`/`assets/`/`scripts/` paths, catalog versions matching frontmatter, and the "N skills" count matching reality. CI (`.github/workflows/ci.yml`) runs the same gate on every push. See [docs/DEVELOPER.md](docs/DEVELOPER.md) for the full change loop.


## Lineage

- Fork origin: vendored from the mermaid project's `.agents/skills/` at its commit dc010ca (2026-09-11, project start) — at that point a verbatim copy of Open Storycraft.
- Verified against the upstream ZIP (`open-storycraft-structured.zip`, downloaded 2026-10-10): the only differences from upstream were our own pre-fork passes recorded in the CHANGELOG. Nothing upstream was dropped.
- Upstream has no public repo or changelog — the ZIP is its only distribution channel. Run `./sync-check.sh` to re-check for upstream drift; any differing file not accounted for in the CHANGELOG is upstream movement to review, not an obligation to take.
- This repo is the source of truth for our library. Changes are ordinary development: add a CHANGELOG entry, bump the skill's version in its frontmatter, and go. There is no re-apply-the-deltas ritual anymore.
